# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add automatic dark mode to the personal website that activates via OS preference (`prefers-color-scheme: dark`), with no JavaScript and no visible change to light mode.

**Architecture:** Append a single `@media (prefers-color-scheme: dark) { ... }` block to the end of `assets/css/main.css`. The block contains override rules for backgrounds, text, links, borders, and shadows. No HTML or JS changes.

**Tech Stack:** CSS3 media queries. The site is a static GitHub Pages page using an old HTML5UP "Miniport" template (jQuery + skel framework, no build tools).

**Reference:** Spec at `docs/superpowers/specs/2026-04-30-dark-mode-design.md`. Color palette table is in §"Color palette" of the spec.

---

## File Structure

Only one file is modified across the entire plan:

- `assets/css/main.css` — append a single dark-mode `@media` block at the end of the file (after the existing closing `}` on the last line). The block is fenced with a comment header for visibility.

No new files. No HTML changes. No JS changes. No new dependencies.

### Task 1: Scaffold the dark-mode block, unify section backgrounds, suppress grain texture

**Files:**
- Modify: `assets/css/main.css` (append at end of file, after the final closing `}` near line 2400)

- [ ] **Step 1: Append the dark-mode media query and background overrides**

Open `assets/css/main.css` and append the following at the very end of the file:

```css

/* ============================================================
   Dark mode (auto, follows OS preference via prefers-color-scheme).
   All overrides live inside this single block. Removing the block
   reverts to the original light-only theme.
   ============================================================ */
@media (prefers-color-scheme: dark) {

	/* Unified section backgrounds */
	.wrapper.style1,
	.wrapper.style3,
	.wrapper.style4 {
		background-color: #1a1a1a;
	}

	/* Nav slightly darker than body to remain distinct */
	#nav {
		background-color: #141414;
	}

	/* Suppress paper-grain texture; flat dark color reads cleaner */
	.wrapper {
		background-image: none;
	}

}
```

- [ ] **Step 2: Visual check — dark mode**

Switch DevTools `prefers-color-scheme` emulation to `dark`. Reload `http://localhost:8000`.

Expected: Top, Research, Editorial, Students, Awards, and Contact sections are all uniformly dark `#1a1a1a`. The nav at the top is slightly darker `#141414`. No paper-grain texture is visible. **Text will be hard to read at this point — that's expected; Task 2 fixes text colors.**

- [ ] **Step 3: Visual check — light mode regression**

Switch emulation to `(no override)`. Reload.

Expected: The page looks identical to the pre-change baseline (Step S4). Light backgrounds, paper-grain texture present, contact section is dark `#303030`.

- [ ] **Step 4: Commit**


### Task 2: Add text colors and suppress white text-shadows

**Files:**
- Modify: `assets/css/main.css` (extend the existing dark-mode block from Task 1)

- [ ] **Step 1: Insert text-related overrides inside the dark-mode block**

In `assets/css/main.css`, find the `@media (prefers-color-scheme: dark) {` block created in Task 1. Inside it, just before the closing `}` of the media query, append:

```css

	/* Body and section text */
	body {
		color: #d0d0d0;
	}
	.wrapper.style3 {
		color: #d0d0d0;
	}
	.wrapper.style4 {
		color: #d0d0d0;
	}

	/* Headings */
	h1, h2, h3, h4, h5, h6 {
		color: #f0f0f0;
	}
	.wrapper.style4 h1,
	.wrapper.style4 h2,
	.wrapper.style4 h3,
	.wrapper.style4 h4,
	.wrapper.style4 h5,
	.wrapper.style4 h6 {
		color: #f0f0f0;
	}

	/* Suppress white halos from light-mode text-shadows */
	.wrapper.style2,
	.wrapper.style3,
	.wrapper.style4 {
		text-shadow: none;
	}
```

The explicit `.wrapper.style3` and `.wrapper.style4` color rules override the existing rules in the file (line ~1619 for style3, line ~1627 for style4) which set hard-coded `#000` and `#999` respectively — those need explicit overrides because their selectors are at the same specificity and our block is later in source order.

The explicit `.wrapper.style4 h1...h6` rule overrides the existing rule at line ~1632 which sets `color: #fff`.

- [ ] **Step 2: Visual check — dark mode**

Switch emulation to `dark` and reload.

Expected:
- Body text in Research/Editorial/Students/Awards sections is light gray `#d0d0d0` and clearly legible.
- Section headings ("Research", "Editorial Service", "Ph.D. Students", "Awards") are slightly brighter `#f0f0f0`.
- Contact section text and headings are also light gray / brighter — readable against the unified `#1a1a1a` background.
- No white halos around any text. (Before this task, "Editorial Service" and similar headings had a faint white outline — that should be gone.)

- [ ] **Step 3: Visual check — light mode regression**

Switch emulation to `(no override)` and reload.

Expected: Page is identical to baseline. Light sections still have the subtle embossed text-shadow (the `text-shadow: 1px 1px 0px #fff` rules in the original CSS are still active).

- [ ] **Step 4: Commit**

```bash

git commit -m "$(cat <<'EOF'
Add dark-mode text colors and suppress white text-shadow halos

Body and section text -> #d0d0d0, headings -> #f0f0f0. Override the
hard-coded #000/#999 colors on .wrapper.style3/style4 and the #fff
heading color on .wrapper.style4. Remove text-shadow on style2/3/4
```

### Task 3: Update link colors for AA contrast on dark

**Files:**
- Modify: `assets/css/main.css` (extend the existing dark-mode block)

- [ ] **Step 1: Insert link overrides inside the dark-mode block**

Inside the `@media (prefers-color-scheme: dark) { ... }` block, just before the closing `}` of the media query, append:

```css

	/* Links / accent — slightly brighter cyan for AA contrast on dark bg */
	a {
		color: #5cc8f5;
	}
	a:hover {
		color: #7dd6ff !important;
	}
```

The `!important` on `:hover` mirrors the existing light-mode rule at line ~1099 which uses `!important` to win over wrapper-scoped link rules. Without it, hover would be inconsistent across sections.

- [ ] **Step 2: Visual check — dark mode**

Switch to `dark` emulation and reload. Hover over a few links: the SSRN/Google Scholar links at the top of Research, several publication titles in the numbered list, and the Ph.D. student names.

Expected: Links render in `#5cc8f5` (a brighter cyan than the light-mode `#43B3E0`). On hover they become even brighter `#7dd6ff`. Clearly readable against the dark background.

- [ ] **Step 3: Visual check — light mode regression**

Switch to `(no override)` and reload.

Expected: Links use the original `#43B3E0`, hover `#43bff0`. No change.

- [ ] **Step 4: Commit**

### Task 4: Update divider/border colors

**Files:**
- Modify: `assets/css/main.css` (extend the existing dark-mode block)

This task is defensive: the current page does not contain `<blockquote>` or `<hr>` elements, but the existing CSS styles them with light-gray borders that would appear as bright lines if either element is added later. Adding the dark-mode override now means the dark theme stays correct as the page evolves.

- [ ] **Step 1: Insert border overrides inside the dark-mode block**

Inside the `@media (prefers-color-scheme: dark) { ... }` block, just before the closing `}` of the media query, append:

```css

	/* Borders / dividers */
	blockquote {
		border-left-color: #2e2e2e;
	}
	hr {
		border-top-color: #2e2e2e;
	}
```

- [ ] **Step 2: Visual check — dark mode**

Switch to `dark` emulation and reload. Scroll the entire page top to bottom.

Expected: No visible bright `#eee` lines anywhere. (The current content has no `<blockquote>` or `<hr>` so this rule is mostly dormant — that's fine.)

- [ ] **Step 3: Visual check — light mode regression**

Switch to `(no override)` and reload.

Expected: Page identical to baseline.

- [ ] **Step 4: Commit**

```bash
git add assets/css/main.css
git commit -m "$(cat <<'EOF'
Add dark-mode borders for blockquote and hr

Override blockquote border-left-color and hr border-top-color to
#2e2e2e so future content using these elements doesn't show bright
```
